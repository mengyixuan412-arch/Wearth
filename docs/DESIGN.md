# Design-wearth

Wearth 的视觉与交互规范。数值全部取自 `CODE/src`，以代码为准。

---

## 1. 基调

复古未来主义（retro-futurist），但**首页和内页是两套版式**，不要互相套用：

| | 首页 `/` | 五个内页 |
|---|---|---|
| 底 | 程序化粉色天空（WebGL） | 纯白 `#ffffff` 底板 |
| 主体 | 3D 折射玻璃字标 | 4:1 主视觉横幅（位图） |
| 秩序 | 准星网格 + 视口相对字号 | 发丝线框 + 12 栏栅格 |
| 字号 | `svw` / `svh` 推导 | 固定档（`text-xs` … `text-3xl`） |
| 指针 | WebGL 流体推挤 | 粉色方格拖尾 |

首页是**招牌**，一屏之内把名字、标语和录入入口讲完；内页是**工作台**，密度、可读性和翻页一致性优先于表演。

三条铁律：

- **界面元素一律低饱和。** 除强调粉外，全站只有黑 / 白 / 米三档中性色。彩色只出现在 3D、主视觉横幅和衣物图片里。
- **交互反馈用点线或药丸，不用大面积填充。** 导航与站内链接是 2px 虚线描边；页内控件是一圈发丝线的药丸，选中态才填一层 7% 的黑。
- **只有首页有 WebGL。** 内页的秩序全部交给线和网格，不要为了统一往内页加 3D。

## 2. 色彩

### 令牌定义

```css
/* 亮色 */
:root {
  color-scheme: light;
  --label:            0, 0, 0;
  --label-d:          54, 54, 48;
  --background-deep:  251, 250, 244;

  --label-1: rgba(var(--label), 1);            /* 主文字 */
  --label-2: rgba(var(--label-d), 0.6);        /* 次要文字 */
  --label-3: rgba(var(--label-d), 0.32);       /* 弱化文字、单位、英文名 */
  --label-4: rgba(var(--label-d), 0.18);       /* 极弱：卡片框、首图外框 */
  --line:    rgba(var(--label-d), 0.1);        /* 分隔线 */

  --background-1:        rgb(var(--background-deep));  /* 页面底（米白） */
  --background-elevated: #efede7;                      /* 浮层底 */
  --background-card:     #fefefe;                      /* 表单格 / 卡片面 */
  --background-paper:    #e9e9ed;                      /* 已定义，当前无引用 */

  --selection-bg: #ff2e88;                     /* 荧光粉：选中态、签名、指针 */
  --accent:       #d53f7d;                     /* 画在浅底上的粉 */
  --accent-soft:  #f27cad;                     /* 画在反色黑块上的粉 */
  --accent-wash:  color-mix(in srgb, var(--selection-bg) 5%, var(--background-card));
  --cubic-66:     cubic-bezier(0.66, 0, 0.01, 1);
}

/* 暗色：加 .dark 到 <html>，由系统 prefers-color-scheme 驱动，界面上没有开关 */
.dark {
  --label:            255, 255, 255;
  --label-d:          230, 232, 232;
  --background-deep:  15, 17, 17;
  --label-4: rgba(var(--label-d), 0.16);
  --line:    rgba(var(--label-d), 0.08);
  --background-elevated: #191b1b;
  --background-card:     #1e2022;
  --background-paper:    #1b1c1f;
  --accent:      #ff81b6;   /* 与亮色互换：深粉画在浅底、亮粉画在深底 */
  --accent-soft: #c4306e;
}
```

### Tailwind 别名

```css
--color-l1 --color-l2 --color-l3 --color-l4 --color-line
--color-b1 --color-be --color-card --color-paper
--color-selection --color-accent --color-accent-soft --color-accent-wash
--color-frame --color-rule-strong
--ease-66
```

用法：`text-l1` `text-l3` `bg-card` `bg-accent` `text-accent-soft` `bg-accent-wash` `border-line` `border-l4` `border-frame` `ease-66`。

`--color-frame` / `--color-rule-strong` 是下面「两档发丝线」那两个值的 Tailwind 别名，
TS 侧同源导出为 `FRAME` / `RULE_STRONG`（`lib/layout.ts`）——
写 class 时用别名，传 `style` 或画 SVG 时用常量，**不要再手写第三份色值**。

### 四档中性文字色的职责

令牌表里写了每一档的定位，但**最容易用错的是 l3 与 l4**，单列一条：

| 令牌 | 亮色 | 做什么 | 不做什么 |
|---|---|---|---|
| `l1` | 100% | 主文字：值、单品名、被读的那个数 | |
| `l2` | 60% | 次要文字：说明句、单位、图表轴标、列表两端的标签与读数 | |
| `l3` | 32% | 弱化文字：占位、英文副标、控件的**未选中态** | |
| `l4` | 18% | **框线**：卡片框、首图外框；以及**禁用态**（超出范围的日期） | **不做文字。** |

`l4` 一度被拿去写角标和占位（「合计 100%」「JPG / PNG」「0/3」这类），
在白底上淡到几乎看不见 —— 它的定位是「极弱的**线**」，不是极弱的字。已全部收回 `l3` 以上。

**控件的未选中态是个例外，仍旧用 `l3`。** 它不是提示文字，是状态色：
`Segmented`、`MetricStrip` 未选中的那几档提到 `l2` 的话，选中与未选中的对比会塌掉，
一排 tab 看起来像全都选中了。

### 三支粉的分工

**不要凭手感在这三个之间挑。**

| 令牌 | 亮色 | 用在 |
|---|---|---|
| `--selection-bg` | `#ff2e88` | `::selection` 背景、签名描边、指针拖尾。**不做按钮、不做填充。** |
| `--accent` | `#d53f7d` | 画在白/近白底上：面板编号、「必填」标记、选中态填充、CheckTag 的底 |
| `--accent-soft` | `#f27cad` | 画在反色黑块（`bg-l1`）上的小标签。亮粉在黑底上才读得出 |

`--accent-wash` 是**混成不透明色**的 5% 粉，专给静息 hover 底。别用 `bg-selection/[0.05]` 代替 —— 半透明会把格线的灰透上来，粉就偏成藕色，和白底的日历格对不上。

### 粉色阶梯

图表与插画共用一支粉的五个深浅档，全部出自下面的「粉色色号」表，**没有新配**：

| 常量 | 值 | 定位 |
|---|---|---|
| `PINK_50` | `#f6e9eb` | 最淡。BLUSH 卡面的底 |
| `PINK_200` | `#FFC4DD` | 柱状图浅档 |
| `PINK` | `#F27CAD` | **锚色**。柱面、点阵、三角箭头 |
| `PINK_INK` | `#D53F7D` | **唯一够当正文读的一档**（对比度约 4:1）。星期名、刊头、编号 |
| `PINK_DEEP` | `#C4306E` | 只进按钮渐变，不进柱状图 |

两条硬规矩：

- **要当文字读的地方只能用 `PINK_INK`。** 更浅的档做文字必糊。
- **柱状图从锚色只往下走一档就停。** 点阵是隔着空白的 6px 小圆点，实际覆盖率约四分之一；柱子是接近实心的色块。同一个色号，覆盖率差三四倍，观感差一个量级 —— 拿阶梯最深的两档去铺满柱面，整根柱子会读成红的。序列之间的区分交给**材质**（购买斜纹 / 养护实心）和交界处一道白色发丝线，颜色只补半档。

### 两档发丝线

内页是白底，令牌 `--line`（暖灰 10%）在白底上被冲得几乎看不见，框线立不住，面板就散成一片白。所以表格、图表、日历这三类**改用一套写死的冷灰两档**：

```ts
export const FRAME       = "rgba(20,20,28,0.20)";   // 面板框、格线、单品网格
export const RULE_STRONG = "rgba(20,20,28,0.88)";   // 页面级结构横线（首图下那一条）
```

- 两档必须拉开：只有一档的话，要么框重得像表格，要么淡得等于没有。「这是一个框」和「这里分区了」是两件事。
- 用中性冷灰 `20,20,28` 而不是令牌的暖灰 `54,54,48` —— **白底上暖灰会泛黄。**
- 代价是这两档**不随暗色态翻转**。当前只有亮色形态实测过；`bg-white` 与这两档线在暗色下不会跟着走，接暗色时要一起处理。

### 粉色色号

**中性底不粉。** `--background-deep`（米白）、`--label-d`（暖灰）、两层转场底色都保持原样。

| 用途 | 亮色 | 暗色 | 位置 |
|---|---|---|---|
| 强调色 | `#ff2e88` | 同 | `globals.css --selection-bg` · `signature-sign` · `fluid-push-pass` · `star-flare` |
| 乱码进场渐变 | `#ff2e88 → #7F0236` | `#ff2e88 → #FF81B6` | `scramble-text.tsx` |
| 光晕拖尾 | `#ff5fa8` | `#e0007a` | `star-flare.tsx` |
| 指针方格 | `#FF4A9E → #FFB0D6` | 同 | `pointer-trail.tsx` |
| 3D 玻璃 tint | `#ff6fa8 → #ffffff` | `#ff9ec4 → #c48ea0` | `glass-stage.tsx` |
| 首屏天空·底 | `#f6e9eb` | `#883a67` | `procedural-background.tsx` |
| 首屏天空·边 | `#cd98c9` | `#0d0006` | 同上 |
| 首屏天空·调色 | `#edddcf` | `#3d1145` | 同上 |
| 录入按钮渐变 | `#F27CAD → #D53F7D → #C4306E → #B42862` | 同 | `add-item-button.tsx` |
| 柱面侧影 | `#E4759F` | 同 | `analysis-charts.tsx` |

按钮那一行在文件里是带 alpha 的 `rgba()` 而不是 hex，照 hex 搜不到。**全部 12 个值：**

```
径向渐变  rgba(242,124,173,0.95) → rgba(213,63,125,0.94)
          rgba(196,48,110,0.96)  → rgba(180,40,98,0.97)
高光      rgba(255,196,221,0.80)   rgba(239,121,170,0.55)
内描边    rgba(238,122,172,0.95)
投影      rgba(196,45,108,0.32)    rgba(196,45,108,0.24)
色散环    rgba(255,120,176,0.40)   rgba(255,150,140,0.32)   ← 后者是暖珊瑚，故意不同色相
加号阴影  rgba(140,28,74,0.50)
```

**推导规则：保持原色的明度与饱和度，只转色相。** 新增粉色照此办理，别凭感觉调 —— 这套颜色彼此有固定关系，手配一个就会脱队。

**天空是三色相，不是单色粉。** 底 352° / 边 305° / 调色 28°，饱和度压在 35–45%。把三个色相收拢到同一段粉再拉满饱和度，整片天空会糊成一块糖 —— 实测过的失败版本。

**光晕那两个拖尾色是选的，不是算的。** 原版「亮橙 + 深蓝」冷暖对撞在粉色系里没有等价解，改按「亮色态用亮粉、暗色态用深粉」处理。

`--code-comment` / `-string` / `-number` / `-keyword` / `-function` / `-tag` / `-operator`，明暗各一套，见 `globals.css`。

## 3. 字体

四套，各有明确领地：

| 令牌 / 常量 | 字体 | 加载 | 用途 |
|---|---|---|---|
| `font-sans` | **TikTok Sans**（可变，wght + wdth） | `FontFace` 运行时加载，注册名 `tiktok` | 标题、品牌名、大号数字、药丸控件的字 |
| `font-ui` | **PingFang SC** 及各平台同位替代 | 系统字，不下载 | 正文、角标、单位、元数据、标签 |
| `fleur` | **Fleur De Leah** | `next/font/google`，weight 400，latin 子集 | **仅穿搭日志**的月份名 |
| `SERIF` | Georgia / Times New Roman / Songti SC | 系统字，内联常量 | **仅穿搭日志**的刊头、星期名、翻月箭头 |

`font-ui` 的字体栈里**不放自有拉丁字**：

```css
--font-ui: "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif;
```

栈首放自有字的话，同一行里英文归自有字、中文回退到苹方 —— 中英混排就成了两个声音。`font-ui` 把两种文字都交给苹方，读起来才是一套。

日志页那两套花体/衬线是**刻意的例外**：日历要读成一张纸质手账，而不是又一张数据表。别把它们扩散到其他页。

### 可变轴

TikTok Sans 是双轴可变字（wght 100–900 + wdth）。宽度轴**只用三档**，各有职责：

| `wdth` | 用在哪 | 例 |
|---|---|---|
| **120** | 页面级大标题、品牌名、弹窗标题 | 首页标语、`个人档案` h1、`添加一件衣物` |
| **110** | 卡片与筛选栏里的小标题 | 衣橱单品名、品类筛选按钮 |
| **105** | 表单里的数值 | 价格 `399`、日期 `2026/08/26` |

```tsx
style={{ fontVariationSettings: '"wdth" 120' }}
```

字重只用两档：`font-bold`（标题与数值）和默认 400（正文）。`font-medium` 仅用于表单里那种既要有分量、又不该抢标题的大号输入值。

### 尺度

**四档正文**。这四档承担全站 91% 的文本节点，新代码不要在它们之间再插新档：

| 档 | 移动 → 桌面 | 用在哪 |
|---|---|---|
| 角标 | `text-[10px] lg:text-xs` | 编号、单位、元数据 —— 即 `META` |
| 标签 | `text-xs lg:text-sm` | 字段标签、控件文字、说明句 |
| 正文 | `text-sm lg:text-base` | 需要读进去的段落、按钮 |
| 强调 | `text-base lg:text-xl` | 卡片标题、次级标题 |

`META` 是共用常量，**从 `components/panel.tsx` 导入，不要各处重写**：

```ts
export const META = "font-ui text-[10px] lg:text-xs uppercase";
```

需要变体时在它上面追加，而不是另起一份 —— 衣橱是 `` `${META} tabular-nums` ``，图表轴标是 `` `${META} tracking-wide` ``。

**展示档**（标题与大数字，按层级递增）：

```
text-lg lg:text-2xl     抽屉/卡片标题
text-xl lg:text-2xl     弹窗标题
text-2xl lg:text-3xl    统计卡片数字、表单大号值
text-3xl lg:text-5xl    页面 h1
text-4xl lg:text-5xl    统计页主数字
text-5xl lg:text-6xl    占位页大标题
```

**表单值三档**（`form-controls.tsx` 的 `valueText(size)`）。同一张表里只准出现一档 ——
混用会让相邻格子的数字看起来不是同一类东西：

| 档 | 值 | 用在 |
|---|---|---|
| `lg` | `text-3xl lg:text-4xl` | 整页表单（个人档案） |
| `md` | `text-xl lg:text-2xl` | 弹窗这种更密的版面（录入单品） |
| `sm` | `text-sm lg:text-base` | 购买评分的商品信息 —— 那一栏只占 12 栏里的 5 栏，还要塞下八个字段 |

> **药丸触发器不跟这三档。** 表单格里「品类」是下拉、「价格」是输入框，层级上是同一类东西，
> 但药丸是粗体加边框，同号字在药丸里的视觉重量要大一截 —— 按数值对齐反而更不齐（实测过）。
> 药丸留在标签档（`text-xs lg:text-sm`），**站在药丸位置上的占位文字也跟着药丸走**：
> 跟错了的话，一选中值就会缩一档，整行跟着跳。

### 数字与单位

**大数后面挂单位，一律「数字 + 小字单位」，不带货币符号：**

```
20 件        22,631 元        27 元/次
```

`analysis-charts.ts` 为此给了两个格式化函数，**按有没有单位后缀选**：

| 函数 | 输出 | 用在 |
|---|---|---|
| `yuan(v)` | `¥20,651` | 行内读数，后面**不跟**单位（最近购入、条形图金额） |
| `amount(v)` | `20,651` | 后面**另挂**单位的大数 |

写成 `¥27` 再跟一个 `/次`，货币符号在前、量纲在后，一个读数被拆成两截；
写成 `¥22,631 元` 则是 ¥ 和「元」重复。两种都不要。

**视口相对**（只给首页标语，随屏缩放保证版面比例恒定）：

```
text-[7.4svw] sm:text-6xl    中文行
text-[6.4svw] sm:text-5xl    英文行
```

> 10px 以下不设档。曾经存在的 9px 与 11px 已并入 10px / 12px —— 它们夹在两档之间没有职责，9px 在图表轴标上也确实读不清。

### 规则

- HUD 类小字统一走 `META = "font-ui text-[10px] lg:text-xs uppercase"`（图表件那一份另加 `tracking-wide`）。
- **`tabular-nums` 在 `font-ui` 上不生效** —— 苹方没有 `tnum` 特性。数字列对齐靠**右对齐**；确需等宽字形的场合用 `font-sans`（TikTok Sans 支持 `tnum`）。
- 正文行高 `leading-relaxed`；标题 `leading-none` 或 `leading-tight`。
- 字体就绪前整树 `invisible`（`ShellGate`），不做 FOUT。

## 4. 布局

### 页面骨架

```
<html> <body>                                html, body { overflow: hidden }
  ThemeModeProvider → ShellMediaProvider → PointerProvider → FullscreenTransitionProvider
    RouteTransitionLayer     转场画布 z-30 + 加载进度条 z-40
    PointerTrail             内页粉色方格拖尾（首页不挂，那里是 WebGL 流体）
    Scrollbar                自绘滚动条
    ShellGate                字体就绪前整树 invisible
      ScrollShell            fixed inset-0 的滚动根
        {children}
```

`ScrollShell` **已接回并包住全部路由**，分两种滚动源：

| 路由 | 滚动 |
|---|---|
| `/` | `ReactLenis` 平滑滚动，`autoRaf: false`，由 R3F 的 `addEffect` 驱动 |
| 其余 | 原生 `overflow-y-auto overscroll-contain no-scrollbar` |

只有首页需要 Lenis —— WebGL 要和滚动同帧。内页没有 WebGL，平滑滚动只会让表格拖泥带水。

### 内页两种根容器

**A. 页面自滚（默认）** —— 衣橱、统计、评分、录入：

```tsx
<div className="relative z-10 px-4 lg:px-14 py-4 lg:py-7">…</div>
<div aria-hidden className="-z-1 fixed inset-0 bg-white pointer-events-none" />
```

**B. 单屏 + 内层滚动区** —— 个人档案、穿搭日志：

```tsx
<div className="z-10 fixed inset-0 flex flex-col px-4 lg:px-14 pt-4 lg:pt-7">
  <SiteHeader title={null} />
  <main className="flex-1 min-h-0 overflow-y-auto no-scrollbar">…</main>
</div>
```

B 不是随手写的：档案页的左栏目录用 `IntersectionObserver` 追当前小节，**需要一个真实的滚动 root**；日志页的星期行是 `sticky`，**需要一个滚动容器**。除这两种需求外一律用 A。

那块 `-z-1 fixed inset-0 bg-white` 是内页的白底板 —— 它盖掉令牌里的米白 `b1`。发丝线的两档是照白底调的，少了这块底板线会偏。

### 竖向节奏

四个内容页从上到下的距离**必须一致**，翻页时首图不能跳：

```
SiteHeader
  pt-4 lg:pt-6      → 首图（4:1）
  HERO_GAP          → 控件条          mt-5 lg:mt-7    （lib/layout.ts）
  pb-2.5 lg:pb-3    → 控件条下的结构横线（RULE_STRONG）
  mt-4 lg:mt-6      → 内容
  mb-16 lg:mb-20    → 页底
```

`HERO_GAP` 是常量不是字面量。各页横线的来源不同（衣橱/统计是筛选栏的 `border-b`，日志是日历框的上边框），但视觉上是同一条线，所以对齐的是「首图底边 → 线」这段整体距离。

### 栅格与留白

```
grid-cols-12       12 栏，贯穿全站
px-4 lg:px-14      标准左右留白（全站统一，首图也铺到这个宽度）
gap-4 lg:gap-6     栅格间距
p-2                点线描边元素的内边距
```

单品网格是**共用边线**的：容器只补上和左（`border-t border-l`），右和下由每一格自己画，相邻两格因此共用一条线，中缝不会叠成 2px。表单格同理，用 `gap-px bg-line` + 每格自铺 `bg-card`，线就是漏出来的底色 —— 最后一行填不满也不会留下半截悬空的分隔线。

### 断点

```
sm 640    md 768    lg 1024    xl 1280    2xl 1536
```

**`lg` = 1024 是移动/桌面分界**，JS 侧同源：`useIsMobile()` 判定 `width < 1024`。hover 态一律 `lg:hover:`（触屏不触发）。

## 5. 组件规范

**复用的判据是「是不是同一类东西」，不是「长得像不像」。**

同一类东西必须共用一份实现：弹窗外壳、照片投放区、下拉菜单、日期选择器、颜色格、
左栏目录、分页器 —— 这些各写各的，迟早在两个页面之间漂出差别，而差别没有任何理由。
判断方法很直接：**如果两处将来必须一起改，那它们就该是一份代码。**

反过来，长得像但职责不同的不要强行合并。同一张抽屉里横排的「基本信息」和竖排的
「材质成分」都是表单格，但一个是单值、一个是可增删的列表，合成一个组件只会让参数表
长成配置文件 —— §5.5 的两套壳、§5.11 照片投放区「只负责框本身」都是这个取舍。

新增共用件时：**写进本章、补进文末的模块清单**。清单里找不到的东西，下一个人就会重写一遍。

### 5.1 主视觉横幅

五个内页各有一张 **4:1 横幅**，标题、编号、中英副标、脚标**全部画在图里**，DOM 不再重复一遍 —— 所以这些页的 `SiteHeader` 传 `title={null}`。

```tsx
<div className="pt-4 lg:pt-6">
  <img
    src="/img/hero/insights.webp"
    alt="衣橱统计 Wardrobe Insights —— 让每一次穿着都看得见价值"
    width={2000} height={500}
    fetchPriority="high"
    className="block border border-l4 w-full h-auto"
  />
</div>
```

| 编号 | 页面 | 文件 |
|---|---|---|
| 01 | 个人档案 | `profile.webp` |
| 02 | 我的衣橱 | `wardrobe.webp` |
| 03 | 穿搭日志 | `ootd.webp` |
| 04 | 衣橱统计 | `insights.webp` |
| 05 | 购买评分 | `score.webp` |

- **按原始画幅铺满，任何方向都不裁。** 标题在最左、拼贴在最右，中间是留白 —— 裁一头就丢一头。
- 宽度铺满 `px-4 lg:px-14` 的内容宽，**不套页内容器的 `max-w`**，否则宽屏上这一页就比别的页窄一截。
- 外面那圈 `border-l4` 是必要的：稿子四边接近白，不描边会和白底融掉。
- 生产：设计稿在 `Design/页面插图/`，已是 4:1，跑 `node tools/build-hero.mjs <稿.png> public/img/hero/<名>.webp`。脚本做两件事 —— 放大到 3344px（稿子 2000px，宽屏显示宽度约 1600px，HiDPI 下等于 0.6 倍密度，直接用会糊）、编码 webp 并**锁 4:4:4 色度采样**（默认 4:2:0 会把粉字和细线的边缘染糊，这几张稿子最吃这一项）。
- `alt` 写图里的完整语义。若页面已有 `sr-only` 的 `<h1>` 念过标题，`alt` 就只写标语，别念第二遍。

### 5.2 面板

两族，**按内容类型选，不要混用**：

| | `components/panel.tsx` | `analysis-charts.tsx` 的 `Panel` |
|---|---|---|
| 用在 | 表单页（档案、录入） | 数据页（统计） |
| 卡面 | `bg-card` + `border-l4` | `bg-white` + `FRAME` |
| 表头 | 编号（粉）· 中文 · 英文 · 右侧 meta/操作 | 编号（粉）· 中文 · 英文 · 右侧操作 |
| 内容区 | 无内边距，格子自己带 | `px-4 lg:px-6 py-4 lg:py-5` |
| 进场 | 走 `ScrambleText` | 不走 |

表头都是三段式，和编号索引的读法一致：`编号 · 中文名 · 英文名 ……… 操作`。
**两族的编号都走 `text-accent`** —— 曾经统计页那一族是灰的，两处面板并排看会觉得不是一家。

> **表头右端不再挂单位。** 统计页那一排 `元 / 件 / 次` 已全部撤掉：单位跟着它修饰的那个数走
> （§3「数字与单位」），挂在表头等于让读者把它记住再套到下面每一个数上。
> 那个槽位现在只放操作（分段控件）。

表单族的内容区不留内边距是有意的：里面的格子自己带 padding 并靠 `gap-px bg-line` 织分隔线，格子边缘直接顶到框上，线才连得起来。

统计页那张 `BLUSH` 卡面是唯一的例外底 —— 一层粉金属渐变加内阴影转折光，**不带外投影**：发丝线体系里所有面板都齐平地坐在白底上，只有一张浮起来会脱队。

### 5.3 药丸控件

页内所有分段、筛选、排序、分页共用一套药丸壳，**不要各写各的**：

```tsx
// 静息
"rounded-full px-3 lg:px-4 py-1.5 font-sans font-bold text-xs lg:text-sm text-l3 lg:hover:text-l1"
// 选中
"bg-[rgba(0,0,0,0.07)] text-l1"
// 带框的（搜索、筛选、排序、下拉）
"border border-line focus-within:border-l1 lg:hover:border-l1 rounded-full"
```

- 选中态是 **7% 的黑**，不是粉。粉留给数据和强调，控件不抢。
- `Segmented` 两档尺寸，别加第三档：`sm` 面板头里的次级控件（字号压在面板标题之下）、`lg` 首图下那条页面级筛选栏。**`lg` 档必须和衣橱筛选栏的药丸同字号** —— 两个页面的同一个位置摆两种大小，翻页会看出来。
- `FilterSelect` 把图标和下拉融成一个控件，**图标即标签**，不再写文字标题。
- 空品类（该分类下 0 件）退到 `text-l3` 但仍可点，不禁用。

### 5.4 下拉菜单

选项**多到平铺会占满一行**、或每项需要图标时才用它；三五个平级选项仍走 5.3 的 `Segmented`。
落地件：`components/dropdown-menu.tsx`（通用壳）+ `sort-menu.tsx`（排序）/ `add-menu.tsx`（添加）。**壳只此一份，不要各写各的。**

两种 `variant`：`select` 选一个值 —— 行有选中态、收起前留 260ms 让对勾落定；`actions` 触发一个动作 —— 无选中态，点完立即收（那 260ms 是给「看清自己选了哪个」的，动作型菜单不需要）。触发器两档 `tone`：`outline` 描边药丸、`accent` 实心强调色。

**不要用原生 `<select>`。** 它渲染的是系统菜单，塞不进图标、选中态也没法按本文档的规矩画。
`FilterSelect` 里那个原生 select 是历史件，只因为「图标即标签、不展示选项外观」才留着。

| 部件 | 规格 |
|---|---|
| 触发器 | 就是 5.3 那颗带框药丸 + 一枚 10px chevron；展开时切到选中态（7% 黑 + `border-l1`），chevron `rotate-180` |
| 面板 | `bg-card` + `border-line` + `rounded-2xl` + 定宽（排序菜单 224px） |
| 行 | 图标 + 文字，`gap-2.5 px-3.5 py-2.5`，字号同药丸（`text-xs lg:text-sm` + `wdth 110`） |
| 对齐 | 默认 `left-0` 对齐按钮左沿；只有控件贴着行末、右展会顶出视口时才改 `right-0` |
| 限高 | 默认不限，面板有多高铺多高；**祖先有 `overflow-hidden` 时必须传 `maxHeight`** |

- **面板是全站唯一带外投影的浮层**：`0 12px 32px rgba(20,20,28,0.10)` + `0 2px 6px rgba(20,20,28,0.06)`。
  这不和 5.2「面板不带外投影」冲突 —— 那条管的是**齐平坐在白底上的卡**，浮层是另一回事：
  白底上再摞一层白面板，发丝线自己分不开两层白，只能靠影子。
- **所有选项一律 `text-l1`，图标同色。** 不用「灰 / 黑」区分选中与否 —— 那会让未选中的七条读起来像被禁用。
  选中只靠两个信号：`bg-accent-wash` 底 + 右侧粉色对勾。
- **分组靠重复图标，不画分隔线。** 一组两条（正序 / 倒序）共用一个图标，重复出现本身就是分组信号；
  再加线只会把这一列切碎，而且同一个菜单里的选项本来就是同一件事，没有哪一刀是真分界。
- **放在弹窗里必须传 `maxHeight`。** 弹窗面板自己是 `overflow-hidden` 的，菜单伸不出去会被齐腰切断 —— 穿搭记录里 11 个分类的面板要 ~600px，实测只露出 7 行。传了之后面板内部滚动（自动带上 `data-lenis-prevent`），切不着了。
- **选中后不立刻关。** 先让对勾落到新的那一行上，停 260ms 再淡出（见 §7 时长）——
  点完即消失的话，用户来不及看清自己点中了哪个。

**可访问性**（这套是自写控件，原生行为得自己补齐）：

```
role="listbox" / role="option" + aria-selected      触发器 aria-haspopup + aria-expanded
↑↓ 循环移动 · Home / End 跳两端                      打开时焦点落在当前选中项
Esc 关闭并把焦点还给触发器 · 点击外部关闭
```

**一条工程约束**：选项表（`lib/wardrobe.ts` 的 `SORTS`）和图标表分处两个文件时，
在菜单里加一道编译期穷尽检查，漏配图标直接构建失败 —— 靠人记是记不住的。

```ts
type Missing = Exclude<Sort, (typeof GROUPS)[number]["items"][number]>;
const _EVERY_SORT_HAS_AN_ICON: [Missing] extends [never] ? true : never = true;
```

### 5.5 表单格

版式语言：**白底 + 一层灰线框 + 大号数字**。

```ts
export const CELL           = "flex flex-col gap-1.5 bg-card px-4 lg:px-5 py-2.5 lg:py-3";
export const VALUE_ROW      = "flex items-end gap-3 min-h-11";
export const valueText = (size) => `font-sans font-medium leading-none h-[1em] p-0 …`;  // 三档见 §3
```

**竖向收得比横向紧。** 一栏里叠着七八格，每格多两像素整栏就多出小半屏；
左右留白则要撑住格子里的大号值，不能跟着收。

`min-h-11`（44px）是**下限，不是随手取的**：数字格的步进器就是 43px，
再往下收它会顶破行高，价格那一格会比隔壁高出来。要更紧只能先改步进器。

- 格子之间**不留间距、只留 1px 线**（外层 `gap-px bg-line`，每格自铺 `bg-card`）。
- 值行定死行高再**底对齐**：数字格的步进器（两颗按钮叠起来 43px）比选择格的单个箭头（28px）高，用 `items-center` 会把两种格子的文字顶到不同高度。
- `<input>` 要压 `h-[1em] p-0`：输入框的盒子默认比文字高一截，里面的字又垂直居中，等于整体上浮半截 —— 数字就会比隔壁格里的汉字高几个像素。
- 粉只落在**「必填」标记、hover 底和步进器**上：面积小、位置固定，不做填充。
- `CheckTag` 是唯一整格填粉的控件（选中态 `bg-accent`），文字用 `text-card` 而不是写死白色 —— 暗色态下 accent 翻成亮粉，字得跟着翻深。
- 反色说明块（`bg-l1` 的黑卡）里的粉标签换 `--accent-soft`。

#### 横排格：标签在左、值在右

窄栏用另一套壳。竖排格把标签和值上下叠，一格吃两行高度；八九个字段排下来，
那一栏就只剩标签和留白：

```ts
export const CELL_ROW       = "flex items-center gap-4 bg-card px-4 lg:px-5 py-2.5 lg:py-3 min-h-12";
export const CELL_ROW_VALUE = "flex flex-1 justify-end items-center gap-2 min-w-0";
```

`NumberCell` 传 `row` 切到这一套。购买评分的「商品信息」整栏走横排 ——
它只占 12 栏里的 5 栏，而且和**单品详情抽屉的「基本信息」是同一类内容**
（一件衣服的属性清单），两处因此是同一种版式：一格一行，值的右沿在一栏里对齐成一条线。

**只给单值字段用。** 季节那种分段、材质那种可增删的列表、尺码那几个并排的围度框，
值本身就不止一行，塞进右半边只会把行撑开，比竖排更乱 —— 这些仍旧竖排。
同一栏里两种格子并存是正常的，不是不一致。

> 单值字段可以两两配成一行（`grid-cols-2`），每格自己仍是横排。
> **可能很长的值（名称）单独占整行** —— 配对之后右半边只剩两三个字的宽度。

### 5.6 可交互元素：点线描边

站内**导航与链接**共用一套 class 常量：

```ts
export const DOTTED_BORDER_BASE = /* 2px 虚线，透明 → lg:hover 变 l1，200ms */;
export const DOTTED_BORDER_BASE_WHITE = /* 同上，hover 色换 white */;
export const DOTTED_BORDER_ACTIVE_BOTTOM = "before:border-b-l1";
```

- 用在：`SiteHeader` 的品牌与导航、`DottedLink`、日志页的翻月箭头、录入按钮的 hover 环。
- 页内的**控件**不走这套，走 5.3 的药丸 —— 表格页上一片虚线框会吵。
- 深色背景（3D 接管全屏时）切 `_WHITE` 变体；元素本体加 `p-2` 让虚线框有呼吸。

### 5.7 文字进场：ScrambleText

```tsx
<ScrambleText text="基础信息" startDelayMs={300} scrambleColors={false} />
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `letterDelayMs` | 80 | 逐字间隔；HUD 类小字用 40，长段落用 10 |
| `startDelayMs` | 0 | 同组元素错开：300 / 500 / 700 |
| `scrambleColors` | true | 乱码期是否着色；HUD 关掉 |

机制：全局单一 **40ms** ticker，元素进入视口且转场开启后才订阅，动画结束即退订。乱码字符集 `A-Z0-9!@#$%^&*+-=?/<>[]{}`。

**当前只用在表单族面板的表头**（`components/panel.tsx`，即档案页与录入页）。数据页和列表页不挂：一屏几十个读数一起乱码，是噪音不是进场。

### 5.8 页面转场

六个模块是六条独立路由：

```
/               主页        标语 + 3D 字标 + 录入按钮
/profile        个人档案     /wardrobe   我的衣橱     /wardrobe/new  录入新衣服
/ootd           穿搭日志     /analysis   衣橱统计     /decide        购买评分
```

导航项定义在 `lib/nav.ts` 的 `NAV_ITEMS`（`{ zh, en, href }`）。站内跳转**不用裸 `<Link>`**，用 `DottedLink`，它先触发转场再导航。

转场是叠起来的两层，都由 `FullscreenTransitionProvider` 的 `startNavigation(href)` 驱动：

| 层 | 组件 | 颜色（暗 / 亮） | 参数 |
|---|---|---|---|
| 径向遮罩 | `RouteTransitionLayer`，z-30 | `#191b1b` / `#efede7` | `duration 0.8` |
| 点阵 | `RouteTransitionDots`，在各 scene 内 | `#0F1111` / `#FBFAF4` | `overlayPixelSize 4` |

两层颜色刻意保持**中性黑白，不带粉**：它们对齐的是 `--background-elevated` 与 `--background-deep`。转场是「翻页」不是「表演」—— 这是用户每次切模块都会看到的半秒，染粉会变成每次都闪一下。

带 WebGL 的路由（当前只有首页）必须给 scene 挂 `RouteTransitionDots` 并传同一组 `OVERLAY_COLORS`，否则转场会在这条路由上断掉。纯 DOM 的内页只走径向遮罩层，不用挂。

### 5.9 页头、网格与指针

原来那套四角 HUD（GMT+8 时钟、SOUND、THEME 三态、旋转地球、`L/D/A/S/T/B` 快捷键）**已整体移除**，换成一条 `SiteHeader`：

```
左上   Wear X Worth（回主页，点线描边）
左下   首页：品牌中英双行 / 内页：留空（title={null}）
右侧   六项导航，中英双行，窄屏换行不溢出
```

首页额外在底部留一行状态：`2026年8月25日 · 星期二 · 28˚C`（`useStatusLine()`）。

- `GridOverlay`（`mix-blend-difference` 的准星网格，线色 `rgba(255,255,255,0.1)`，桌面 3 列 / `<1280` 2 列，边距 `56 / 16`）**只挂在首页**。
- `PointerTrail`（18px 方格拖尾，`#FF4A9E → #FFB0D6`，900ms 淡出，按格坐标去重，无残留时自动停帧）挂在**除首页外的全部路由** —— 首页那里是 WebGL 流体推挤，两套指针效果不叠加。

### 5.10 弹窗

三个弹窗（**录入单品 / 添加分类 / 穿搭记录**）共用 `components/dialog-shell.tsx`，不要各写各的 —— 它们是同一层级的东西，标题字号、遮罩浓度、关闭按钮大小只要有一处不同，连着开两个就看得出来。

```tsx
<DialogShell zh="穿搭记录" en="OOTD Entry" label="8 月 21 日的穿搭记录"
             onClose={close} panelClassName="max-w-[1120px]" action={<删除按钮 />}>
  <div data-lenis-prevent className="flex-1 min-h-0 overflow-y-auto">…</div>
</DialogShell>
```

外壳定死的部分：

| | 值 |
|---|---|
| 挂载 | `createPortal` 到 `document.body` |
| 遮罩 | `bg-l1/25` + `backdrop-blur-md`，`p-4 lg:p-8` |
| 面板 | `bg-card` + `shadow-2xl` + `border-l4`，`max-h-[88vh]`，方角 |
| 表头 | `px-14 lg:px-16 py-3.5 lg:py-4`，下边 `border-line`，无独立底色 |
| 标题 | **居中两行**：上行英文 `META + tracking-[0.2em] + text-l3`；下行中文 `text-base lg:text-xl` + `wdth 120` |
| 关闭 | 方形 `w-7 lg:w-8`，`border-l4`，`✕`，hover 转 accent；绝对定位在表头右端、垂直居中 |
| 次要操作 | `DIALOG_ACTION` 常量，放在关闭按钮左边的 `action` 槽 |

四条不能省的理由：

- **必须 Portal 到 body。** `ScrollShell` 在首页套了一层 Lenis 容器，弹窗留在那棵子树里滚轮会被 Lenis 先接走，内部滚不动；挂到 body 也顺带脱离所有祖先的层叠上下文。
- **滚动容器必须带 `data-lenis-prevent`。** Lenis 全局接管滚轮，不加这个属性弹窗里永远收不到滚轮事件（实测滚 5 下 `scrollTop` 仍是 0）。
- **弹窗内不套 `no-scrollbar`。** 页面上可以藏滚动条，弹窗里必须让人看见还有内容没露出来。
- **标题居中、操作绝对定位。** 表头因此不受操作按钮多少的影响：有「删除这天」和没有，标题都在同一个位置。左右 `px-14 lg:px-16` 的留白就是给两端操作预留的跑道。

内容区的底色与版式各自决定：穿搭记录走白纸族（`bg-white` + `FRAME` 发丝线，和它翻起来的那张日历同一种纸），录入单品与添加分类走卡片族（`bg-card` + `--line`）。

**已知未统一**：小节标签有两套 —— 录入单品用 `01 / 选择分类`（线性步骤，斜杠读作「第几步」），穿搭记录用 `01 关联单品 ITEMS`（面板表头三段式）。两者各自成立，暂不强行合并。

### 5.11 照片投放区

四处上传（个人档案全身照 / 录入单品衣物照 / 穿搭记录当日照 / 购买评分三张截图）共用 `components/photo-drop.tsx`。它只负责**框本身**；框外的标题、说明、「移除」按钮由调用方摆 —— 四处的外围布局本来就不同，塞进组件只会让参数表长成配置文件。

| | 值 |
|---|---|
| 空态 | `bg-be/50` + `border-2 border-frame border-dashed`，hover 转 accent |
| 填充 | `border border-frame`，图 `object-contain` |
| `lg` | `+` `text-4xl lg:text-5xl` · 粗体主文案 `text-sm lg:text-base` · 说明 `text-l2 text-[11px] lg:text-xs` |
| `sm` | `+` `text-xl` · 只有 `JPG / PNG`（`META text-l4`），标题写在框下 |
| 读取中 | `+` 变 `…`，主文案变「处理中…」 |
| 读不出来 | 说明位换成 `这张读不出来，换一张`（accent） |

- **空态的虚线是常驻的，不是 hover 才显形的那套点线描边（§5.6）。** 这里的虚线是「这块地方是空的、等你放东西」的静态语义，不是交互反馈。
- **线色用 `--frame` 不是 `--line`。** 投放区都坐在白底或近白的卡上，暖灰 10% 在白底上几乎看不见（同 §2「两档发丝线」）。
- **一律 `object-contain`，不用 `cover`。** 尺码表裁掉一角就读不全，单品裁掉袖子就认不出是哪件。
- **点框即换图，框外只留「移除」。** 不再另设「更换」按钮 —— 填充态的框本身就是可点的，两个入口做同一件事只是多占一格。
- **标题写在框中央，不顶在框下。** 四处一律 `lg` 档 —— 评分页三格并排的宽度也站得下粗体主文案，框下便不必再留一行，空态因此只是干净的三个框。
- `sm` 档目前**无人使用**，留着给真正窄到站不下标题的位置。

### 5.12 日期：一个控件、两种写法

全站凡是「挑一个日期」都走 `components/date-picker.tsx`，凡是「显示一个日期」都走 `lib/date.ts` 的 `formatDate`。这两条不留例外 —— 之前三处日期各写各的，同一张抽屉里「购入日期」是 `2026-04-08`、选择器却是 `2026/08/26`，读起来像两个系统的数据。

**存储与显示是两种写法，各有各的读者：**

| | 写法 | 出处 | 谁在读 |
|---|---|---|---|
| 存储 | `2026-08-12` | `dateKey()` | 代码 —— 可直接字符串比大小、可按前缀切出年月（统计的趋势图就是这么分组的） |
| 显示 | `2026/08/12` | `formatDate()` | 人 |
| 显示（短） | `08/12` | `formatDateShort()` | 人，且**年份已由上下文交代过** |

短版只用在单品详情那一排穿着日期（都在这件衣服的生命周期内）。列表和读数一律用完整版 —— 少了年份，「去年的 08/12」和「今年的」就分不出来。

`lib/date.ts` 是全站日期的唯一出处，`dateKey` / `today` / `parseKey` / `sameDay` / `monthMatrix` 都在里面。**不要在别处再写一份** —— `wardrobe.ts` 和 `ootd-store.ts` 曾各自实现过一遍 `today()`，两份都得记着「不能用 `toISOString()`（走 UTC，东八区晚上会记成前一天）」，漏一处就是一个只在晚上复现的错日期。

**不用原生 `<input type="date">`。** 各浏览器长相不同、日期格式跟着系统语言变，更要命的是没法在格子上打点 —— 而「这一天已经有记录了」正是养护与穿着记录最需要一眼看见的信息。

#### 触发器两个变体，面板只有一个

| `variant` | 长相 | 用在 |
|---|---|---|
| `box`（默认） | 方框 + 值 + chevron，跟着旁边的输入框走 | 单品详情的养护记录 / 穿着日志 |
| `cell` | 无边框，值走 §5.5 的 `valueText(size)` + `wdth 105`，底对齐 | 录入弹窗的购入日期 |

`cell` 底对齐是必须的：这一格的日期要和隔壁「购入价格」那格的数字落在同一条基线上。

#### 面板

沿用 §5.4 下拉菜单那一套浮层机制 —— **portal 到 body 用 fixed 定位，自己量触发器的矩形**。绝对定位会被祖先的 `overflow` 裁掉（抽屉正文与弹窗正文都是 `overflow-y-auto`）。下方站不下、且上方更宽敞时自动朝上展开；触发器贴着右边（抽屉就在屏幕右侧）时把面板收回视口内。

| | 值 |
|---|---|
| 面板 | `bg-card` + `border-line` + `rounded-2xl` + `p-3.5`，宽 268px（7 列 × 34 + 内边距），`z-[60]`（压过抽屉与弹窗的 `z-50`） |
| 投影 | 同 §5.4：`0 12px 32px rgba(20,20,28,0.10)` + `0 2px 6px rgba(20,20,28,0.06)` |
| 月份 | `2026年8月`，`font-sans` bold + `wdth 110`；左右两枚 chevron，整月出界时置灰 |
| 星期 | 一 二 三 四 五 六 日，**周一起头**，`META` + `text-l3` |
| 日格 | 6 行固定 42 格，翻月时面板高度不跳；圆形 `w-8 h-8` |

日格四态，**都是中性的，只有选中和打点是粉的**：

| 态 | 画法 |
|---|---|
| 选中 | `bg-accent` + `text-card`（§2 指定的「画在白底上的选中态填充」那一支；字不写死白色，暗色态 accent 翻亮粉时字得跟着翻深） |
| 今天 | `bg-[rgba(0,0,0,0.07)]`，同 §5.3 药丸的选中底 |
| 悬停 | 同上那层 7% 黑 |
| 出界 | `text-l4`，用 `aria-disabled` 而不是 `disabled` —— disabled 的按钮接不到焦点，方向键会在它那里断掉 |

**有记录的日子在数字下方打一个 3px 粉点。** 养护记录打已记账的日子，穿着日志打已关联的日子 —— 省得挑中一天才被「这天已记」挡回来。选中态下点翻成 `bg-card`，粉底上才读得出。

#### 三条容易踩的

- **选中之后不自动收起。** §5.4 下拉菜单那种「停 260ms 再关」在这里不成立 —— 挑日期常常要改两次（点错一天、或者翻个月再看看），面板一落定就消失的话每次都得重新点开。让它留在原地，用户下一步点别处、按 Esc 或再点一次触发器，它自己就收。
- **Esc 走捕获阶段并掐断冒泡。** 这个控件开在抽屉和弹窗里，而它们的关闭监听挂在 `document` 的冒泡阶段。不掐断的话按一下 Esc 会连着把外面那层一起关掉 —— 用户想收的只是这张月历。
- **面板上的 `pointerdown` 也要掐断 React 冒泡。** 面板 portal 到了 body，但在 **React 树里**它仍是抽屉/弹窗的后代，事件照样冒上去；而那两层的「点外面就关」判的是 DOM `contains`，面板不在它们的 DOM 子树里 —— 于是点一下日历就把整个抽屉关掉了。

#### 两个刻意的例外

不走上面这套写法的地方只有两处，都是有意的：

- **穿搭日志**（整页日历与它的弹窗）用花体 + 衬线的 `August 1 / 2026`。那一页要读成一张纸质手账而不是又一张数据表（§3）。它和选择器共用 `monthMatrix`，所以同一个月的格子排布是一致的。
- **首页状态行**用中文长写法 `2026年8月26日 · 星期二 · 28˚C`。那是一句话，不是一个读数。

### 5.13 颜色：圆点一行 + 弹出取色器

全站凡是「挑一个颜色」都走 `components/color-field.tsx`，它自己弹 `components/color-picker.tsx`。三处在用：录入弹窗的**色系**、购买评分的**颜色**、个人档案的**肤色**。

**不用原生 `<input type="color">`。** 它弹的是操作系统面板，长相由系统决定，在这套白底灰线框里会突兀地跳出来；也挂不上「最近用色」这类自带信息。

预设色板从 lib 取，不在页面里现拼：

| 常量 | 出处 | 档位 |
|---|---|---|
| `COLOR_PRESETS` | `lib/wardrobe.ts` | 六档色系 白 `#F2F0EC` / 黑 `#1F1F21` / 灰 `#8C8C8C` / 红 `#B23A3A` / 蓝 `#7A93BC` / 粉 `#D9A8BD` |
| `SKIN_PRESETS` | `lib/profile-options.ts` | 四档肤色，取自 `SKIN_TONES` |

录入与评分吃的是**同一份** `COLOR_PRESETS` —— 两处判定的是同一件事（附录 D-4 的色系），色板分家就等于两套口径。

#### 圆点这一行

```tsx
<div className={CELL}>
  <CellLabel zh="肤色" hint={presetOf(SKIN_PRESETS, skinTone)?.label ?? "自定义"} />
  <div className={VALUE_ROW}>
    <ColorField value={skinTone} onChange={…} presets={SKIN_PRESETS} customLabel="自定义肤色" />
  </div>
</div>
```

| | 值 |
|---|---|
| 行 | `flex flex-wrap items-center gap-2.5` |
| 圆点 | `rounded-full w-8 h-8`，`lg:hover:scale-110`（150ms） |
| 选中 | `ring-2 ring-l1 ring-offset-2` |
| 未选中 | `border border-line` |
| 末位触发器 | 选了预设时是虚线加号（`border-2 border-line border-dashed` + `text-l3`，hover 转 accent）；选了自定义色就填成那个颜色并套上选中环 |

- **选中态是一圈黑环，不是填粉。** 圆点本身就是颜色，填一层粉会把它盖掉。这也是 §5.3「粉留给数据，控件不抢」在这里的落法。
- **预设不写文字。** 颜色本身就是标签，圆点旁边再写「白 / 黑 / 灰」是多一层转译。档名有额外含义时（肤色的「中性偏暖 · 自然肤色」）挂到 `CellLabel` 的 `hint` 上，随选中项变；hex 挂到面板表头右端的读数位（§5.2）。要读「当前命中哪一档」用组件导出的 `presetOf()`。
- **组件只负责圆点这一行。** 字段标签、档名读数、说明句由调用方摆 —— 三处的外围版式本来就不同，塞进组件只会让参数表长成配置文件（同 §5.11）。

#### 取色器面板

| | 值 |
|---|---|
| 面板 | `bg-card` + `border-l4` + `rounded-xl` + `shadow-2xl`，`p-3`，宽 `w-64`（256px） |
| 弹出 | portal 到 body 用 `fixed`，**竖向与触发器居中对齐**；横向默认贴右侧，右边站不下翻到左侧 |
| 饱和度 × 明度 | `h-40` `rounded-lg`，白 → 本色 横向、透明 → 黑 纵向 |
| 色相条 | `h-4` `rounded-full`，七段标准色相渐变 |
| 手柄 | `w-4 h-4` 白色 2px 描边圆点，外加 `0 0 0 1px rgba(0,0,0,0.30), 0 1px 3px rgba(0,0,0,0.25)` |
| 读数 | 色块 `w-7 h-7` + `META` 的 `Hex` + 六位输入框（`bg-be/50`，`focus:border-accent`，回车或失焦提交，非法值回滚） |
| 最近用色 | `grid-cols-7` × 2 行 = 14 格，存 `wearth:recent-colors`；不足时用内置色板补满 |

- **落点要量，高度要实测。** 横向在打开时量触发器矩形，`rect.right + 12 + 256 > innerWidth` 就翻边 —— 窄屏上这一行的末尾离右边缘只剩几十像素，不翻会整个弹出视口外。竖向按触发器圆心居中，再整体夹回视口（下限优先于上限：视口比面板矮时宁可顶着上沿）。**面板高度用 `ResizeObserver` 实测，不写死** —— 带取样条时比不带高出一大截，拿固定值算居中必有一种形态是偏的。
- **色相单独存 state，不从 hex 反推。** 纯黑和纯白的 hex 里没有色相信息，拖到方块左下角再拖回来，色相会被重置成红色。
- **`pointerdown` 走捕获阶段。** 面板里的拖拽会 `setPointerCapture`，冒泡阶段收不到外部按下，「点外面就关」会失灵。
- **Esc 走捕获阶段并掐断冒泡**（同 §5.12）。三处调用方里有两处是弹窗，它们的关闭监听挂在 `document` 的冒泡阶段；不掐断的话按一下 Esc 会连取色器带弹窗一起关掉。取色器没开时这个监听不挂，Esc 照常传给弹窗。
- **最近用色只在真正存下一条记录时记**（`rememberColor`）。拖动过程中每一帧都是一个新颜色，边拖边记会把色板冲成一片渐变。

##### 从图上取色

面板里可以多一条**取样条**：一张按 `contain` 画进 canvas 的缩略图，悬停出放大镜，点击落色。
四处调用各传各的图，标题也各自不同：

| 调用方 | 传的图 | `sampleLabel` |
|---|---|---|
| 录入单品 / 单品详情 / 购买评分 | 那件衣服或那件商品的照片 | `商品取色`（缺省） |
| 个人档案 · 肤色 | 用户的参考照片 | `照片取色` |

- **`sampleImage` 传了才渲染。** 没传（档案页以外的场景没图）或图还没上传时，这一条不画。
- **必须是同源 dataURL。** 外链图会把 canvas 标记成「已污染」，`getImageData` 直接抛
  SecurityError。全站的图都走 `lib/image.ts` 缩成 dataURL 存，这个条件天然成立。
- **取 5×5 邻域的平均色，不取单像素。** 织物有纹理、褶皱有高光和阴影，
  取中一个高光点会得到近白色；取肤色时尤其明显。
- 用 canvas 而不是 `<img>` + 坐标换算：图画进画布之后，鼠标位置到像素就是一比一的
  （只差一个 dpr 系数），不必再推 `object-contain` 的留白偏移。留白保持透明，点在留白上不取色。
- 放大镜 9×9 源像素放到 72px，`imageSmoothingEnabled = false` —— 放大出来要是一格一格的
  像素，不是一团糊。
- **键盘走不到 canvas。** 取色的键盘路径是 hex 输入框与最近用色那一排按钮，两处都可聚焦；
  canvas 上没有能聚焦的目标，硬造一个像素网格出来也点不准。

另有一颗**屏幕吸管**（hex 那一行末尾），只在 Chromium 系渲染 —— `EyeDropper` 是
Chrome / Edge 独有，Safari 与 Firefox 没有。**探测放在挂载后做**，不在渲染期读 `window`：
SSR 首帧按「有」画、水合时按「没有」画会报 hydration 不匹配。

### 5.14 左栏目录：SectionNav

表单页左栏的分节目录。**个人档案与购买评分共用这一份**（`components/section-nav.tsx`）——
两页的这一栏本来就是同一个东西：编号 + 中文名 + 「填了几项 / 共几项」+ 一颗完成点，
点一下跳到那一节，滚动时高亮跟着走。

```
Sections            ← 顶上一条 border-t-l1 的黑线，落在 aside 上沿
01  基础信息   3/3 ●
02  参考照片   0/1 ○
```

| | 规格 |
|---|---|
| 表头 | `META` + `tracking-[0.2em]`，上黑线（`border-t-l1`）下细线（`border-b-line`） |
| 条目 | `py-3 lg:py-3.5` + `border-b border-line`；编号 `META`（当前项 `text-accent`，否则 `l3`） |
| 名字 | `text-xs lg:text-sm`，当前项 `font-sans font-bold text-l1`，否则 `text-l2` |
| 读数 | `${META} text-l3 tabular-nums`，写作 `done/need` |
| 完成点 | 6px 圆点，填满 `bg-accent`，未满 `border border-l3` |

三条实现约束：

- **`done / need` 由调用方算。** 什么算「填完了」是各页自己的事：档案数的是字段，
  评分数的是必填三项与出没出分。组件只负责画和跳。
- **分母取「这一节要往下走必须有的东西」，不是字段总数。** 评分的商品信息有八个字段，
  但只有必填三项决定出不出分；把选填也算进分母，进度永远填不满，读起来像没做完。
- **观察器的 root 跟着版式走。** 档案页是「单屏 + 内层滚动区」（§4 的 B），要把那个
  滚动容器传进 `rootRef`；评分页是「页面自滚」（A），不传，按视口判定。
  `rootMargin` 压到容器上沿附近（`0px 0px -68% 0px`），取带内最靠上的一节为当前节 ——
  不压的话，下半屏的小节一露头就抢走高亮，读起来永远超前一节。

### 5.15 分页：Pager

列表分页（`analysis-charts.tsx` 的 `Pager`），**摆在面板正文的右下角**，跟在被翻的那张表后面。
表头那一排是筛选与排序，决定「看的是什么」；翻页决定「看到第几行」，属于这张表本身。

```
‹  1  ›        ‹ 1/3 ›
```

- 形态走 §5.3 的药丸壳：一圈发丝线、圆角、箭头静息 `l3`、hover 转 `l1` 并铺 7% 黑底；
  到头的那一侧压到 `l4` 并 `cursor-not-allowed`（这是**禁用态**，不违反「l4 不做文字」）。
- **一页和多页共用同一个壳**，只是一页时两颗箭头都到头、读数写作 `1` 而不是 `1/1`。
  几张卡并排时右下角摆着形状不一的两种东西最扎眼 —— 有没有下一页，靠箭头的明暗说，
  不靠换一套长相。
- **一表一个页码。** 共用一个的话，在品牌那张翻到第 2 页，单品排行会跟着跳走。
- **换排序 / 筛选就回第一页。** 换了口径还停在第 3 页，看到的是一批没有上下文的行。
- **序号按全表连续编**，第 2 页从 11 起，不是每页从 01 重来 —— 那是排行榜，重编会把名次读错。
- 页数多到一排铺不下时（衣橱那一页 5 页以上）追加一个**跳转框**：药丸形输入框，
  绑本地草稿而不是页码本身（直接绑的话敲「12」会先跳到第 1 页），回车或失焦才提交，
  越界的数字**夹回区间不报错** —— 用户要的是「去最后一页」。

### 5.16 单品关联日历：WearCalendar

单品详情里的「挑哪几天穿过」浮层（`components/wear-calendar.tsx`）。
**它是穿搭日志那张日历的缩印版**（那张的格内画法见 §5.19，这里不跟），不是通用日期选择器：格子里放的是当天那张 OOTD 照片，
竖版 3:4、白纸细线分格，和 `/ootd` 同一种纸。

挑日期是盲选 —— 用户记不住 8 月 12 号穿的是哪套；把照片摆出来，点哪张是看着定的。

| | 规格 |
|---|---|
| 面板 | 322×~400，`bg-card` + `border-line` + `rounded-2xl` + 浮层投影 |
| 刊头 | 花体年月 + 左右翻月箭头 |
| 格子 | 3:4，`FRAME` 细线分格，有照片就铺照片（未关联 70% 透明） |
| 关联态 | 格子**正中一颗 6px 实心粉点**；压在照片上时补一圈 1.5px 白边 |
| 落点 | **优先从按钮右沿向右浮出**；右边塞不下才退回上下展开，下方不够再朝上 |

- **任何过去的日子都能点**，那天有没有照片都行 —— 点没照片的一天会就地建一条只有单品的
  OOTD 记录（PRD 6.4 允许「先传照片、稍后关联」，反过来同样成立）。
  未来的日子点不动：还没穿过的一天不该给 CPW 的分母加数。
- **只有一种标记。** 「这天有没有别的穿搭记录」不标 —— 那对当前这件衣服没有行动含义，
  多一种粉点只会让人先去猜自己选中了什么。
- 关联结果在详情页按**照片**摆出来（3:4 网格），不是一排日期标签：这一节回答的是
  「这件穿去过哪几天」，照片一眼能认，`08/12` 认不出来。那天还没传照片的，
  那一格就只写日期 —— 拿灰块或占位图去填会让人以为图挂了。

### 5.17 图表的轴与分页表

统计页的几张图共用两条口径。

**轴标注写成「维度 / 单位」，两根轴都要有。**

```
支出 / 元                        件数 / 件
  ┌──────────────              ┌──────────
  │  ▮ ▮ ▮                     │ ▨ ▨ ▨
  └──────────────              └──────────
              月份 / 月                单次成本 / 元
```

纵轴标在左上、横轴标在右下。刻度只有两端的裸数字时（衣橱规模那张的 `1 … 12`），
**两端都挂上单位**（`1 月 … 12 月`）—— 不说单位读不出是月还是周还是第几件。

一句话把两根轴合在一起说（曾经的「件数 × 单次成本区间（元）」）不行：
读者得自己拆开、还得猜哪半句配哪根轴，而 `×` 会读成「件数乘以成本」。

**分页表定高，最后一页补等高的空行。**

不补的话最后一页只剩两条时表格会缩掉一截，翻回上一页又弹回来，整片栅格跟着上下跳。
补的方式是**真组件套一层 `invisible`**，不是写死一个 px 值 —— 行高由图片框、条形轨道
和字号共同决定，写死的数一改样式就对不上。**空态也要撑到满页高度**。

> 同处一个栅格行的几张表**取同一个每页行数**：补足空行之后各自的高度就由行数定死了，
> 行数不同，栅格按最高的那张拉齐，矮的几张底下会空出一块。
>
> **条形图的 `max` 取全表最大值，不是当前页的。** 按页取最大，翻页时那一页最长的一根
> 又会铺满整格，几页之间的长度不可比。

### 5.18 报告追问

购买评分的报告下面接一段对话（PRD 6.6）。**它不是一个聊天窗口，是报告的延长线** ——
接在报告正文下方、同一张面板里往下走，不做右侧抽屉也不做浮层：用户问的每一句都指着
上面那几行分维度得分，隔到另一个容器里就得来回对照。出分之前整段不渲染 —— 没有报告，
就没有可追问的东西。

#### 不用气泡

微信那种左右分置的圆角气泡是**大面积填充**，和 §1 铁律二正面冲突，摆进这一页会立刻
读成另一个产品。这里用**问答条目**：

| | 画法 |
|---|---|
| 问 | 整行 `text-l1` + `font-sans font-bold` + `wdth 110`，前置一枚 `META` 的 `Q` 角标 |
| 答 | 整行 `text-l2` + `leading-relaxed`，正文档（`text-sm lg:text-base`） |
| 分隔 | 每组问答之间一条 `border-line`；不画框、不铺底 |
| 输入 | 底部常驻，走 §5.3 那颗带框药丸，右端一枚发送箭头 |

一问一答共用一条竖直节奏，靠**字重与颜色**分主次，不靠左右分置 —— 这和衣橱详情、
统计面板里「标签 / 读数」的读法是同一套。

#### 假设重算条

「降到 400 呢」这类问题的回答**不是一段文字，是一条差异条**（PRD 6.6、ARCHITECTURE §5 ⑥）：

```
假设   价格 ¥580 → ¥400                综合 78 → 84
       ③ 价格合理性  12 → 18
       其余四项不变
```

- **只列变了的维度。** 五项全铺出来，读者得自己找哪一行动了。
- 新值 `text-accent`，箭头前的旧值压到 `l3` —— 旧值是背景，新值才是答案。
- 左上角一枚 `META` 的「假设」角标常驻，整条 `bg-accent-wash` 铺底。
  **它必须一眼区别于上面那份报告**：报告是存档的事实，这条是没发生的事。
- **不复用 `ScoreReport` 的进度条。** 那几根条说的是「这一项拿了多少分」，差异条说的是
  「变了多少」，同一种画法会让人以为上面那份报告被改写了。

#### 等待与出错

**这是全站第一个真有等待窗口的地方** —— §6「没有骨架屏」的前提是数据都在本地，
到这里不成立。等待不新造一套：用 §5.7 的 `ScrambleText` 铺一行乱码占位，走 HUD 档
（`letterDelayMs 40`、`scrambleColors false`），拿到回答后逐字落定。全站的文字进场
本来就是这个语言，再添一个转圈或三点跳动等于多讲一种方言。

出错照 §6 的口径走 `text-accent`、话术给下一步。没配 key 或调用失败时**只有这一段降级**，
上面的报告照常 —— 分是本地规则引擎算的，不该被一条外部依赖拖垮。

#### 三条预设追问

出分后、用户还没开口时，输入框上方摆三颗预设问题的药丸（§5.3）：

```
为什么③扣得最多？        如果便宜 100 呢？        和我衣橱里那几件差在哪？
```

**空输入框是这个功能最高的门槛。** 用户看完报告的疑问是具体的，但把疑问组织成一句
问话是另一回事；给三条按得下去的，第一句就有了。三条按报告的实际情况生成 —— 扣分
最多的那一维、价格维度、有佐证单品的那一维。

### 5.19 穿搭日志：日历格里的照片

月视图的每一格是 3:4，有记录就把当天那张 OOTD 铺进去（`app/ootd/page.tsx`）。

**照片要从格线上收进来。** 格子之间只隔 1px 细线，照片铺满的话，连着记录的几天会连成
一整片色块，看不出是几天 —— 而这一页的意义正是「一格一天」的积累。

| | 值 |
|---|---|
| 内缩 | `p-1 lg:p-1.5`（移动 4px / 桌面 6px）。相邻两天之间因此有 13px 空白（两侧各 6 + 中间 1px 线） |
| 落点 | 内边距加在**按钮**上，不是图片上 |
| 画法 | 图片 `w-full h-full object-cover` |

- **内缩写在按钮上，hover 底色才铺得满整格。** 底色画的是按钮的背景盒，padding 在背景盒
  之内；写到图片上的话，可点区域会比看起来的照片大一圈，鼠标停在缝里也算命中。
- 没有照片的格子外观不变 —— padding 只改变图片的尺寸，空格子里本来就没有东西被它推动。
- **缩印版不跟这一条。** §5.16 的 `WearCalendar` 格子只有 40px 宽，同样 6px 内缩要吃掉
  近三分之一，照片就认不出是哪套了；而那里的格子本来就靠细线分隔，也不存在连片的问题。
  两张日历共用 `monthMatrix` 的排布，不共用格内的画法。

## 6. 状态：空 / 加载中 / 出错

这三类状态没有单独的组件，但有统一的口径。**全站没有红色语义色** —— 粉是唯一的强调色，
出错也用它；也**没有插画式空态** —— 全站只有五张主视觉横幅是位图，空态再来一张会脱队。

### 空数据

| 场景 | 表现 |
|---|---|
| 照片投放区（§5.11） | `bg-be/50` + 2px 常驻虚线 `border-frame`，框中央「＋ 上传一张清晰全身照」+ 一句说明 |
| 面板级空态（决策记录、本季未穿、穿搭记录里的空分类） | 一句 `l2` 的陈述，不加图标不加按钮 |
| 未出结果（评分报告） | 面板正文 `flex-1` + `justify-center`，两句说明居中 |
| 依赖前置输入的格子（款式、尺码数据） | 值位上写「请先填写品类」 |
| 定高分页表（§5.17） | 补等高空行；**空态也撑到满页高度** |
| 取色器的取样条（§5.13） | 没图**整条不渲染**，不画空画布 |

四条原则：

- **说「接下来做什么」，不只说「这里是空的」。** 决策记录的空态是
  「尚未保存记录。衣橱数据变化后，同一件衣服的评分也会随之更新。」——
  前半句是状态，后半句是这个模块存在的理由。
- **该占位的占位，不该占的别占。** 定高表补空行、空态撑满页高，是为了不让邻居跟着重排；
  而照片投放区下面那行「已上传 / 移除」在空态**不渲染** —— 它常驻的话，
  框底下永远空着 32px，而空态才是那一格大部分时间的样子。
- **占位文字跟着它将要变成的那个控件走。** 药丸位上的占位用标签档，输入框位上的用值档 ——
  跟错了的话，一填上值那一行就会跳（§3）。
- **陈述，不安慰。** 不用感叹号，不写「哎呀」「暂时还没有哦」。
  「本季标签的单品都已穿过。」就够了。

> **已知缺口**：衣橱页筛选到零件时没有空态，只剩一片空网格。该补一句
> 「没有符合条件的单品」并给一个「清除筛选」的出口。

### 加载中

| 场景 | 表现 |
|---|---|
| 字体未就绪 | `ShellGate` 把整树 `invisible`（保留布局），**不做 FOUT** |
| 图片正在压缩 | 投放区的 `＋` 变 `…`，主文案变「处理中…」 |
| 路由转场 | 径向遮罩 `z-30` + 顶部进度条 `z-40`（§5.8） |

**没有骨架屏，也不需要。** 数据全在 localStorage，同步读出，不存在等待窗口 ——
造一个假的加载态只会凭空多出一帧闪烁。接后端之后再议，那时才是骨架屏该出场的地方。

### 出错

| 场景 | 表现 |
|---|---|
| 图片读不出来 | 投放区的说明位换成「这张读不出来，换一张」，`text-accent` |
| 本地存储写入失败 | 页脚的状态读数换成「保存失败 · 存储空间不足」，`text-accent` |
| hex 输入非法 | **静默回滚**到上一个合法值 |
| 页码跳转越界 | **夹回区间**，直接去最后一页 |
| 评分维度不可算 | 不报错，按可算权重归一，界面标注「本次评分基于 N 个维度（共 5 个）」 |

三条原则：

- **能自己纠正的不报错。** hex 回滚、页码夹回、维度归一 —— 用户要的是结果，不是一条提示。
  错误提示留给用户**必须自己动手**才能解决的事（换一张图、清出存储空间）。
- **出错用 `--accent`，不引入红色。** 全站的语义色只有粉一支；为出错单开一个红，
  等于在一个「只有黑白米 + 一支粉」的体系里破一个例（§1 铁律一）。
- **话术给下一步，不给错误码。** 「这张读不出来，换一张」而不是「解码失败 (0x8007)」。
  写入失败那一句是唯一带原因的，因为原因（存储空间不足）直接决定了用户要去做什么。

## 7. 动效

### 缓动

```
--cubic-66: cubic-bezier(0.66, 0, 0.01, 1)   主缓动，Tailwind 别名 ease-66
ease-out                                      色彩过渡
cubic-bezier(0.25, 1, 0.5, 1)                 浮层淡入
cubic-bezier(0.22, 1, 0.36, 1)                进度条
```

JS 侧同款：`customCubic()` 是 `cubic-bezier(0.66, 0, 0.01, 1)` 的数值解。

### 时长

```
200ms    点线描边 hover、药丸与边框的 transition-colors
300ms    主题过渡
500ms    浮层淡入淡出
180ms    下拉菜单淡入淡出 + 260ms 选中停留（§5.4）—— 浮层那一档的例外：
         500ms 是给大面积转场的，菜单拖半秒会让人以为点了没反应
660ms    形变（duration-[0.66s] ease-66），如录入按钮的 hover 缩放
800ms    全屏转场、图片显影
```

一律附 `motion-reduce:transition-none`。

### 滚动

```tsx
<ReactLenis options={{ lerp: 0.1, smoothWheel: true, syncTouch: true, anchors: true, autoRaf: false }}>
useEffect(() => addEffect((t) => lenis.raf(t)), [lenis]);
```

**Lenis 必须由 R3F 的 `addEffect` 驱动，不要自建 rAF** —— 自建会让 WebGL 读到慢一帧的滚动值，DOM 同步的元素会抖。这只对首页成立；内页走原生滚动，别往上套。

翻路由时滚动位置手动归零（`history.scrollRestoration = "manual"`，连打两帧 `scrollTo(0,0)`）；带 hash 时改为跳锚点，偏移 96px。

### 滚动驱动的分段区块

长区块用「容器高 = N × 视口高 + 内层 sticky」实现分段：

```tsx
<div style={{ height: `${8 * viewportHeight}px` }}>
  <div className="top-0 sticky" style={{ minHeight: `${viewportHeight}px` }}>{stageContent}</div>
</div>
```

按 `floor((scrollTop - sectionY) / (height / N))` 得到 segment，映射到不同阶段内容。当前无页面在用，接长叙事区块时照此办理。

### 指针

统一 PointerBus，每帧一次把浏览器坐标归一化为 UV（**y 轴翻转**），React 侧走不可变快照，WebGL 侧走可变 `Vector2`。指针离开窗口 / 失焦 / 切标签页时回中。

## 8. WebGL 层

**只有首页用。** 内页没有 canvas。

### 分层

```
renderOrder  -10   程序化背景（全屏面，NoBlending）
              0    3D 模型（玻璃材质，layer 10）
             10    转场点阵
             12    全屏接管的大型模型
             20    DOM 同步的图片平面
```

玻璃物体放 **layer 10**，折射用的场景 FBO 渲染时把相机 mask 设为 1 排除它们，避免自采样。

### DOM ↔ WebGL 同步

图片不用 `<img>`，DOM 只放空占位框，WebGL 按归一化屏幕矩形 `uRect` 绘制：

```
uRect = [left/W, 1 - (top + h)/H, w/W, h/H]     注意 Y 轴翻转
```

矩形采样节流：近视口每帧测，远处每 **12 帧**错峰测一次，其余帧用滚动增量平移缓存值。

### 玻璃材质关键参数

```
uIorR 1.15  uIorG 1.18  uIorB 1.22
uRefractPower 0.72   uChromaticAberration 0.14   uLoop 3
亮色  shininess 120  fresnelPower 1  fresnelStrength 0.24  brightness 0.78  contrast 0.9
暗色  shininess 100  fresnelPower 3  fresnelStrength 0.72  brightness 0.6   contrast 0.98
tint  亮 #ff6fa8 → #ffffff     暗 #ff9ec4 → #c48ea0     沿模型局部 Y 渐变
```

亮色态用 Beer-Lambert 吸收，暗色态用 Hard Light 混合。

字标模型是 `public/model/wearth.glb`，由 Blender 无头生成（`tools/make_script_model.py`，Caveat + `--fit height`；具体参数见 `tools/README.md`）。调参判据只有一条：**只看 dpr=2 的整站实拍，别信 Blender 预览** —— 预览里清晰的笔画凹槽进折射材质会被完全冲掉，字能读靠的是笔画之间真的有透空的缝，不是表面起伏。

### 相机

```
baseFov = 桌面 60° / 移动 38°
fovY = 2 · atan(tan(baseFov/2) / aspect)
z = 24（可随场景推到 32）
```
